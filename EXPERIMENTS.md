# Experiments

Required by brief section 6. Judges want to see whether we can tell genuine emergent behaviour from hardcoded behaviour, randomness, prompt effects or setup artefacts. Negative results count.

## Protocol

- Every run goes through `experiments/run.py` with a config in `experiments/configurations/`. The runner records the seed, params, git commit, dirty flag and package versions for each run.
- Three seeds minimum; five for any result we headline. Report mean, sd and n across seeds, not a best run.
- Commit before a run we plan to cite, so the record points at real code.
- Before calling anything emergent, run the controls that apply:
  - **Hardcoded:** is the behaviour written anywhere in code, rules or prompts? Ablate the mechanism we credit and check the behaviour goes away.
  - **Randomness:** compare against a random or shuffled baseline with the same seeds.
  - **Prompt effects** (if an LLM is involved): paraphrase the prompts and swap the order. Does the behaviour survive?
  - **Setup artefacts:** change world size, timing and initial conditions. Does it still happen?
- Write up a failed experiment the same day, in the Negative results section.

## Setup calibration

This is setup, not an experiment and not a result. It sets the world's difficulty with scripted bees before any AI run, as the spec requires. Recorded 2026-11-06 by the phase 1 build session (Claude Code).

**Target**, in spring with hornets present: oracle bees (told where the bloom is) deliver on most trips, rule bees rarely, random bees almost never. That leaves room above the rule bees for a colony that learns, and shows the task is possible with knowledge of the bloom.

**Measure.** The spring delivery rate is trips that delivered divided by trips that ended in spring, summed over both springs of a 2-year run (`spring_rate` in each run's summary). Mean and sd are across seeds.

**Setup.** Configs `experiments/configurations/calibrate_{oracle,rule,random}.toml`, full-size world (80 x 48, 4 seasons of 250 ticks, 2 years), seeds 0, 1 and 2. Each point varies base life L (`base_life`), `min_bloom_distance` and maze `openness` through `--set` overrides, recorded in each run's record.json. Code at commit 27af856, `git_dirty: false` for every run. Hornet constants fixed for all points: `ambush_rate` 0.02, `ambush_wait` 4, `hornet_speed` 0.8. The 45 runs took 96 s of wall time on 4 CPUs.

**Before these runs.** Exploratory probes (not recorded, and not cited for numbers) found four problems that no setting of the three knobs could fix. They were fixed in code first, in commits 2e19f63 to 128e459:
- a hornet that stung a bee kept chasing it at equal speed and stung it every 10 ticks until it died;
- every hornet re-rolled ambush each tick, so they all camped on the bloom;
- rule bees stayed stuck when nothing was left to explore in their chosen direction;
- deliveries were counted in the season they happened but trips in the season they started, which skewed seasonal rates.

The changes are listed in DECISIONS.md as agent proposals awaiting Jacob.

**Chosen values:** L = 500, `min_bloom_distance` = 55, `openness` = 0.15 (point `L500_d55_o0.15`). There, oracle bees deliver on 0.708 of spring trips (sd 0.191, n = 3), rule bees on 0.024 (sd 0.041, n = 3) and random bees on 0.000 (n = 3). These are now the defaults in `src/digital_life/sim.py` and are set explicitly in `rule_bees.toml`, `random_bees.toml` and `oracle_bees.toml`.

**What the calibration showed**
- Life was the binding knob. At the spec's starting L = 250, oracle bees delivered on 0.524 of spring trips (sd 0.272). One sting near the bloom halves a bee's life, and at L = 250 that usually left too little to get home.
- A bloom farther away (`min_bloom_distance` 65) and a more open maze (`openness` 0.25) both lowered the oracle rate (0.585 and 0.591). The open maze raised rule bees to 0.067 but also raised stings per trip, because hornets reach bees more easily.
- Stings stay high even for oracle bees: 1.208 per spring trip (sd 0.439) at the chosen point. Hornets wait at their earlier sting spots, which lie on the bees' route home. A colony that learns to avoid those spots or warn others has room to beat this.
- Colonies are small. Mean colony size over 2 years is 4.326 for oracle bees, 2.727 for rule bees and 2.521 for random bees, against a cap of 12 and a queen floor of 2.
- Spread across seeds is wide (oracle per-seed rates 0.875, 0.75, 0.5). Three seeds were enough to choose a setting, not to report a result.

**Limits.** Only one point per knob was tried around the chosen values, with 3 seeds each. The rule-bee rate (0.024) rests on one delivery in one seed. Over a whole 2-year run, rule bees made 1, 0 and 2 deliveries in seeds 0, 1 and 2 (`deliveries` in per_seed).

## Pre-registration

Written 2026-11-06, before any real model call by a bee mind, and committed under a subject starting "Pre-registration:". The analysis below is fixed now. Anything changed later is listed under "Amendments" with its date and reason, and marked as made before or after the main runs.

### Shared design

- **Conditions and configs** (all in `experiments/configurations/`): `full`, `no_talk`, `no_memory`, `labels_good_bad`, `frozen_hornets` (AI bees, full-size world, 2 years), and the scripted baselines `rule_bees` and `random_bees`. Every AI arm uses `claude-haiku-5-5`, effort low, thinking disabled, structured output, the same system prompt template (`prompts/bee_system.txt`) and the same perception renderer (`src/digital_life/render.py`). The conditions differ only in what the spec says they change.
- **Seeds:** 0, 1 and 2 for every AI arm; 0 to 4 for the scripted baselines. A seed fixes the maze, the bloom sites and the initial hornet genomes, so arms are compared seed by seed (paired). Any result that goes in the README headline is extended to seeds 3 and 4 for the arms it compares, budget allowing; otherwise it is reported as n = 3.
- **Same commit:** all main runs, baselines included, run at one committed code state (`git_dirty: false`), and replay offline from `experiments/llm_cache/` with `LLM_MODE=replay`.
- **Reporting:** for every measure, the per-seed values, mean, sd and n. No best runs. No run is dropped: a crashed run, or one where more than 5% of decisions fell back to `wait` (`mind_error`), is reported and flagged.
- **What counts as a difference:** with n = 3 we make no significance claims. A difference between two arms is called consistent when it has the same sign on every paired seed (3 of 3; 1 in 8 by chance if the arms are the same) and the mean paired difference is larger than the sd of the paired differences. Anything weaker is reported as "no consistent difference".
- **Censoring:** a season with no delivery gets `first_delivery` = 250 (the season length). Measures with no data (no trips ended, no sounds made) are reported as missing, not as zero.

### E1: learning and culture

- **Hypothesis:** AI bees with memory and hive talk (`full`) gather more than bees without talk (`no_talk`), without memory (`no_memory`), and the scripted rule and random bees.
- **Primary measure:** total `deliveries` per run (both years, `final_metrics` in record.json).
- **Secondary:** `delivery_rate`, `median_to_bloom`, `stings_per_trip`, `bees_mean`, per season and in total.
- **Comparisons:** `full` against each of `no_talk`, `no_memory`, `rule_bees`, `random_bees`, paired by seed 0 to 2.
- **Supported if** `full` > each comparison arm, consistently. If `full` does not beat `rule_bees`, that is a negative result about the AI mind and is written up as one.

### E2: arms race

- **Hypothesis:** evolving hornets adapt to the AI colony: their stings per trip rise from year 1 to year 2, more than with `frozen_hornets`.
- **Primary measure:** change in stings per trip, year 2 minus year 1, from metrics.jsonl (stings / trips_ended over the three seasons with hornets in each year).
- **Secondary:** hornet gene means (smell, hearing, ambush) at the end of each season with hornets; hornet damage per bee-tick outside the hive.
- **Comparison:** `full` against `frozen_hornets`, paired by seed 0 to 2.
- **Supported if** the change is larger under `full`, consistently. Gene drift alone, without a change in stings, is reported as drift, not adaptation.

### E3: seasonal memory

- **Hypothesis:** the colony finds the spring bloom sooner in year 2 than in year 1, because knowledge outlives the bees that found it; with hive talk switched off it does not.
- **Primary measure:** `first_delivery_y1_spring` minus `first_delivery_y2_spring` (ticks; positive means earlier in year 2), censored at 250.
- **Comparison:** `full` against `no_talk`, paired by seed 0 to 2.
- **Also reported,** to separate culture from individual memory: whether any bee alive at the start of year 2 spring was alive during year 1 spring, and whether the first year-2 spring forager had heard a coordinate within 3 cells of the spring bloom at home before leaving.
- **Supported if** the difference is positive under `full` and larger than under `no_talk`, consistently.

### E4: signals

- **Hypothesis:** with neutral sounds, the sounds come to be tied to context (made near moving things, or near bright cells); with the names "good noise" and "bad noise" the tie is there from the start, because it comes from the words.
- **Primary measure:** mutual information, in bits, between which sound a bee makes (sound-1 or sound-2, over decisions that make a sound) and its context at that decision (moving thing in view, bright cell in view, both, neither), from the `ctx` field of decision events.
- **Control for chance:** a permutation test within each run: shuffle the sound labels across that run's sound-making decisions 1,000 times; report where the observed value falls.
- **Time course:** MI in year 1 against year 2 in `full`; MI in the first 250 ticks in `labels_good_bad` against `full`.
- **Listener response (secondary):** the share of `flee` and `go_home` decisions triggered by hearing each sound, against the share at timer decisions.
- **Supported if** MI in `full` is above the 95th percentile of its permutation distribution in at least 2 of 3 seeds. If it is not, neutral sounds stayed meaningless, which is reported as a negative result.

### Further measures (all arms, descriptive)

- **False location claims in hive talk:** every coordinate pair in a `say` text, classed as within 3 cells of a bloom cell of the current or previous season, within 3 cells of a moving thing the speaker saw, or neither (unsupported). Reported as shares per arm.
- **Naive avoidance:** for each bee's first decision triggered by seeing a moving thing, before it was ever stung (from `sting` events), the share that chose `flee` or `go_home`. Compared across `full`, `no_talk` and `no_memory`.
- **Hardcoding audit:** before results are written, grep code, prompts and configs for any rule that ties a sound, a direction or a place to a context. The no-hints and leak tests (tests/test_mind_prompt.py) must pass at the run commit.

## Pilot (phase 2): one full-size spring, not a result

A plumbing and sizing check, run after the pre-registration commit and before any main run. n = 1, so nothing here is a finding. Run directory: `experiments/results/pilot_full_spring/20261106T100558Z/seed-0` (config `pilot_full_spring.toml`: condition `full`, seed 0, full-size world, stopped at tick 250, commit c2052a2, `git_dirty: false`). **Degenerate patterns checked.**
- *All bees waiting:* no (31 of 355 decisions were `wait`).
- *Never leaving home:* no (bees spent 0.145 of their ticks at home; 11 trips started).
- *Endless sounds:* the opposite. Bees almost never make a sound (1 of 355). This is not a plumbing fault: the prompt states the sound's cost (1 life), which is a world rule from the spec. Changing the cost or the wording to get more sounds would be tuning for a result, so nothing was changed. It is a risk for E4: if sounds stay this rare in the main runs, mutual information cannot be estimated, and E4 is reported as a negative result as pre-registered. Flagged to Jacob.
- *Notes as a diary:* bees write a note at every decision, so the 12-note store holds only about the last 60 ticks. Places found earlier survive in the "places you know" landmarks, which come from the bee's own sightings, not from notes. Not changed.
- *Collapse:* none. The colony grew from 6 to 7, so no world adjustment is proposed.

**What the bees did (qualitative, one run).** Bee 1 saw bright cells at tick 94 and chose `go_to (41, 28)`. It picked up at tick 100, was stung at the bloom at ticks 102 and 113 by the same hornet, fled, and carried it home at tick 183 with 23 life left (46 after the delivery), which hatched bee 6. At tick 124, fleeing while carrying, it made the run's only sound, with the note "heading home W to report, alerting others". At home, bees passed on coordinates of moving things, and 31 of the 47 `say` texts contain the word "avoid", for example "Moving things seen east near (27,17); avoid that area". The prompt never says moving things cause harm or that anything should be avoided; the no-hints test checks for that word. Whether this warning changes what listeners do is a question for the main runs (naive avoidance, E1).

**Sizing for the main runs (projection, not a measurement).** If later seasons cost about the same as this spring, a 2,000-tick run takes about 8 times the pilot: roughly 22 minutes and $0.70, so the 15 AI runs (5 arms x 3 seeds) cost roughly $10 and need running in parallel. Winter, larger colonies and longer memories will move both. The replay cache took 3.5 MB for the pilot's 504 calls (about 7 KB a call), so the main runs would add roughly 300 MB to the repository unless the cache is compressed first.
